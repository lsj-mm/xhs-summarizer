# 工具箱

一个本地网页工具箱：**左侧是工具列表，点哪个右侧就出现哪个工具的面板**。
启动后打开 <http://127.0.0.1:8787/>，地址栏会记住你上次用的工具（`#/notes`、`#/tax-rate`）。

| 工具 | 说明 |
|---|---|
| 📝 小红书视频转笔记 | 粘贴分享链接 → 下载转写 → 按内容类型整理成 markdown |
| 💰 税率计算 | 五合一：工资/个税（含年终奖对比）· 房贷（含组合贷）· 提前还款 · 车贷（含真实年化）· 增值税换算；打开后用顶部标签页切换 |
| 📚 编程英语 | 编程词汇查询 + 技术例句 + 日常口语练习；复用已配置的 DeepSeek，中文讲解 |
| 🔎 多语言关键字 | Python / C++ / Java / 前端 / MySQL / Go 关键字速查，含 AI 补充解释与真实 GitHub API 示例 |
| 🎲 彩票模拟摇号 | 大乐透 / 双色球 / 快乐8：官方历史数据、走势统计、单式/复式/胆拖模拟；内置竞彩足球参考，仅供娱乐 |
| 🎓 学习路径与考核 | 按主题和目标生成阶段路径、资源入口和阶段考核，严格执行 3 次机会、80 分通过、不过重学 |
| 🔍 代码审查 | 接入 OpenCodeReview，对本地项目做全量扫描/Git 变更审查，生成行级问题与 Markdown 报告 |

「税率计算」的五个标签页也可以用地址直接打开，例如 `#/salary`、`#/mortgage`、`#/prepay`、`#/carloan`、`#/vat`。

再加新工具**不用改任何代码**，详见「怎么再加一个工具」一节。
下面先讲税率计算，再讲编程英语、多语言关键字、彩票模拟、竞彩足球和学习路径。

## 模型设置（云端 / 本地）

模型选择遵循两条规则：

1. 工具自己设置了大模型 → 用工具自己的；
2. 工具没有单独设置 → 用首页左下角「⚙ 默认模型设置」。

可选的厂商包括 DeepSeek、自定义 OpenAI 兼容接口和**本地模型**。本地模型举例：

| 本地服务 | Base URL | 模型名示例 |
|---|---|---|
| Ollama | `http://127.0.0.1:11434/v1` | `qwen2.5:7b`（先 `ollama pull qwen2.5:7b`） |
| LM Studio | `http://127.0.0.1:1234/v1` | 填 LM Studio 里加载的模型名 |
| vLLM | `http://127.0.0.1:8000/v1` | 填 vLLM 启动时指定的模型名 |

本地模型通常不校验 key，设置里可以留空；但服务本身要先启动，且模型名必须填。
学习路径、代码审查、首页默认模型都支持本地模型；小红书设置里的「内容总结」也会出现本地模型选项。

## 税率计算（五个标签页）

打开「税率计算」后，顶部标签页切换五个计算器；每个标签页的输入互不干扰（内部 id 都带前缀）。

**① 工资 / 个税**：输入税前月薪、发薪月数（12、13、14、15…填几就按几个月工资算）、社保与公积金基数、专项附加扣除，再按当地比例填五险一金
（个人 / 单位各自一列），得到全年税前收入、全年个税、全年工资到手、月均到手、单位月成本，
以及一张逐月表（累计应纳税所得额、适用预扣率、当月个税、当月到手，最后一行为**全年合计**）。

- 个税用**累计预扣法**：累计应纳税所得额 = 累计收入 − 累计(起征点 5000 + 个人五险一金 + 专项附加扣除)，
  当月税额 = 累计应纳税所得额 × 预扣率 − 速算扣除数 − 累计已缴。所以**跳档那个月个税会明显变多**，全年总额不变。
- **发薪月数大于 12（13/14/15…薪）**：多出的工资按年末发放计入累计收入，但不再重复扣五险一金和起征点；
  如果单位把第 13 薪当年终奖发，请选 12 薪并把金额填到下面的年终奖里。
- **年终奖**：按「月薪 × 发薪月数」推算全年工资，比较单独计税与并入综合所得，并给出含奖金后的全年到手。
- 五险一金比例默认值只是一份常见配置，**各地差别很大**（还有缴费基数上下限），请按当地公布比例改。
- 工伤、生育一般只有单位缴，所以个人列留 0。

**房贷计算器**：房屋总价、首付比例、年利率、年限，选等额本息或等额本金 →
月供（等额本金显示首月/末月）、利息总额、还款总额、按年还款计划、可展开每期明细。

**车贷计算器**：车价、首付比例、年利率、期数（12/24/36/48/60 快选）→ 月供、利息总额，
并估算**含购置税的落地总花费**（购置税 = 车价 ÷ 1.13 × 10%，新能源车请取消勾选）。

三者的计算都集中在 `static/tools/_shared/finance.js`（纯函数），并有一份可跑的回归测试：

```powershell
node tools/check_finance.js
```

用例对得上公开的房贷计算示例（如 100 万 / 30 年 / 4.9% → 月供 5307.27 元），
并检查「各期本金之和正好等于贷款额」这类不变量，避免四舍五入留下尾差。

### 成都口径（2026 年度）

「工资计算器」默认套用成都 / 四川的现行参数（也可切到自定义）：

| 项目 | 成都 2026 年度 |
|---|---|
| 社保缴费基数 | **4699 ~ 23493 元/月**（全省社平 7831 元 × 60%~300%） |
| 养老保险 | 单位 16%，个人 8% |
| 失业保险 | 单位 0.6%，个人 0.4% |
| 工伤保险 | 单位 0.2%~1.9%（按行业分八类，个人不缴） |
| 医疗保险 | 单位 6.75% ＋ 生育 0.8% ＋ 大病医疗互助 0.75%，个人 2% |
| 住房公积金 | 基数 **2330 ~ 32969 元/月**，比例 5%~12%（单位与个人同比例） |

- 填了工资会自动**按上下限封顶/保底**，并在界面上提示「已按下限 / 上限计算」；
- 公积金基数**留空或填 0 表示单位不缴公积金**（有的单位没有这项），此时不会按上下限抬到下限；
  默认会跟随社保基数，手动改过之后就不再自动跟随；想重新按社保基数缴，点输入框旁的「同社保」按钮即可；
- 政策参数集中在 `static/tools/_shared/presets.js`，每年调整只改这一个文件（里面写了数据来源链接）；
- 来源：四川省人社厅 2026 年度通知、成都市医保局 2026 年度口径、成都住房公积金管委会通知（页面底部有链接）。

### 年终奖：单独计税 vs 并入综合所得

填一个年终奖金额，直接给出两种方式各自的税额、哪个更省、省多少，并提示**临界点**：
3.6 万正好是 3% 档上限，多发 1 元就掉到 10% 档，反而少拿 2300 多元。
（全年一次性奖金单独计税政策已延续至 2027-12-31。）

### 提前还款测算

输入贷款额、利率、期限、已还期数、提前还款金额，选「减少月供（期限不变）」或
「缩短期限（月供不变）」，得到节省利息、扣除违约金后的净省、新月供（或提前还完的期数）、
以及提前还款后的按年还款计划。

实测：100 万 / 30 年 / 4.9%、还满 36 期后提前还 20 万 —— **减月供省约 16.1 万利息，缩期省约 39.3 万利息**。

### 车贷的真实年化

车贷常有「服务费 / 前置利息」，只看合同利率会被误导。填上手续费后，工具用现金流 IRR 算真实年化：

实测：10 万 / 36 期 / 合同 4.5% / 手续费 5000 元 → **真实名义年化 7.95%**、按月复利的**有效年化 8.24%**。
不填手续费时结果会精确回到 4.50%（可用来交叉验证算法本身没跑偏）。

### 组合贷

房贷页支持组合贷：公积金部分与商业部分各自设金额与利率、分别计息，给出月供合计、利息合计、
以及把两笔合并后的按年还款计划。

> 这些工具是**估算器**，不是官方口径：社保比例与基数上下限、公积金比例、个税优惠政策、
> 房贷利率（多为「LPR + 基点」且每年调整）、车贷的贴息与服务费，都会让实际数字与这里不同。

## 编程英语

一个「编程词汇查询 + 日常口语练习」的英语学习助手，复用工具箱里已配置的总结模型（默认 DeepSeek），
不需要另外填 key。

- **词汇查询**：输入单词、短语，或一句中文想翻成英文。返回文字音标、编程语境释义、2 个技术例句、
  常见搭配、易混辨析和记忆提示。
- **口语练习**：选每日站会 / 代码评审 / 技术面试 / 咖啡店点单等场景，先给 3-5 句示范表达，
  再让用户用英语回复；反馈时先肯定，再指出 1-3 个最值得改的问题，并给更自然的版本。
- **语音输入**：点「🎤 语音」说话（最长 60 秒），浏览器录音后交给已配置的转写服务识别，
  结果填进输入框，可改完再发送；录音临时存在 `work/_english_voice/`，识别完立即删除。
- **美式发音播放**：点击英文单词，或句子后的 🔊，用浏览器的 `en-US` 语音朗读；
  输入框旁的「🔊 试听」可以朗读整句。优先选 Microsoft Aria / Jenny / Guy 等 en-US 语音。
- **跟读评测**：点句子后的 🎯 设为跟读目标，再点 🎤 朗读；识别后给出词级匹配度，
  绿色是识别到的词，红色是漏读/没识别出的目标词，橙色是多识别或可能读错的词。
  它衡量的是「ASR 识别匹配度」，不是音素级发音分。
- **水平切换**：入门 / 进阶 / 高级，影响讲解深度和例句难度。
- **本地记录**：对话存在浏览器 localStorage 里，刷新不丢；点「新对话」清空当前模式。

**关于发音评测**：跟读评测做的是转写文本和目标句的词级对比，能发现漏读、多读、明显读错的词，
但**不能给音素级的发音打分**；转写文本一样不代表发音标准。真正的发音评分需要 Azure Speech
Pronunciation Assessment、Speechace 这类语音评测服务。实时语音对话则需要流式 ASR + LLM + TTS，
目前实现的是「录完 → 转写 → 回复」的轮次式交互。

### 接入发音评分（Azure / 讯飞）

跟读后点「🎧 发音评分」会调用你选的服务，返回发音、准确度、流利度、完整度（讯飞还有标准度）
以及词/音素级结果。在「编程英语」左侧的「发音评分设置」里选择 **Azure** 或 **讯飞**。

**讯飞语音评测（推荐先用，免费额度）**

1. 登录讯飞开放平台，创建应用并添加 **语音评测（流式版）**；
   创建应用后默认有 **每日 500 次**免费调用（以控制台显示为准）。
2. 在控制台拿到 **APPID、APIKey、APISecret**。
3. 页面里选「讯飞」并填三项 → 保存；或使用环境变量：

```powershell
$env:XUNFEI_APP_ID="你的 APPID"
$env:XUNFEI_API_KEY="你的 APIKey"
$env:XUNFEI_API_SECRET="你的 APISecret"
```

   改完环境变量后重启服务（`python run.py`）。环境变量优先于 config.json。
4. 讯飞走 WebSocket（`wss://ise-api.xfyun.cn/v2/open-ise`），后端用项目内的
   `websocket-client` 连接；音频会先转成 16kHz/16bit/单声道 PCM。
5. 计费和隐私：每次评测消耗讯飞免费额度/套餐次数；音频会发到讯飞。

**Azure（可选）**

1. Azure 门户 → 创建 **Speech** 服务，区域例如 `eastasia`，定价层可选 F0/S0。
2. 「密钥和终结点」里复制 **KEY 1** 和 **Region**。
3. 页面里选「Azure」填 key/region，或设置 `AZURE_SPEECH_KEY` / `AZURE_SPEECH_REGION` 后重启。
4. 后端把录音转成 16kHz PCM WAV，调用 Pronunciation Assessment REST；每次会产生 Azure 费用。

不点「发音评分」时，跟读匹配完全在本地/现有 ASR 上完成，不消耗这两家的额度。

> 目前代码接了 Azure 和讯飞；Speechace 的接口形状不同，要接的话需要再加一个 provider 适配。
> 讯飞返回 401/403 通常是 APPID/APIKey/APISecret 不匹配，或应用没添加「语音评测（流式版）」服务。

局限：音标和发音建议是文字，不能替代真人或音频示范；AI 生成的例句与解释可能有误，
重要术语建议再对照官方文档。实现见 `xhs/english.py`（提示词、语音转写、长度限制）、
`xhs/pronounce.py`（Azure / 讯飞分发）、`xhs/xunfei.py`（讯飞 WebSocket 评测）、
`static/tools/english.html`（页面、设置、录音、朗读、跟读与对话渲染）和
`static/tools/_shared/readback.js`（词级匹配纯函数）；接口 `POST /api/english/chat`、
`POST /api/english/transcribe`、`POST /api/english/pronounce`。
跟读匹配：`node tools/check_readback.js`；Azure 离线测试：`python tools/check_pronounce.py`；
讯飞离线测试：`python tools/check_xunfei.py`（都用假响应，不联网）。

## 多语言关键字

一个面向开发者的跨语言关键字速查页，覆盖 **Python、C++、Java、前端（JavaScript）、MySQL、Go**。

- **本地速查**：内置 30 条常用关键字（每种语言 5 条），每条给一句话说明、可运行示例、注意点和官方文档链接；
  支持关键字搜索和语言筛选。
- **AI 补充**：本地没有收录，或想要更细的解释时，点「让 AI 解释」，按当前语言范围调用 DeepSeek 生成对照说明。
- **Python 调第三方 API**：页面给出 `requests` 调 GitHub Search API 的完整步骤
  （查文档 → 发请求 → `raise_for_status()` → 解析 JSON），并提供一个真实的「试调 API」按钮，
  由后端 Python 代理请求 GitHub。
- **MySQL 查询示例**：`LIKE`、`FULLTEXT`（中文 ngram）、`EXPLAIN` 的 SQL 与索引注意点。
- **前后端衔接**：`fetch` + `encodeURIComponent` + 防抖 / `AbortController` 的示例。

实现：`static/tools/keywords.html`、`static/tools/_shared/keywords-data.js`、`xhs/keywords.py`；
接口 `POST /api/keywords/ai`、`GET /api/keywords/github`。

## 彩票模拟摇号

一个基于官方历史开奖数据的娱乐性模拟选号工具，覆盖 **大乐透 / 双色球 / 快乐8**。

- **大乐透**：单式、单式多注、复式、前区胆拖、模拟套餐；单注 2 元，追加 3 元/注。
- **双色球**：单式、单式多注、复式、红球胆拖、模拟套餐；单注 2 元。
- **快乐8**：选 1 ~ 选 10、单式多注、复式、胆拖、模拟套餐；单注 2 元。
  复式按 `C(选号个数, 选几)`，胆拖按 `C(拖码, 选几 - 胆码)` 计算注数。
- **数据来源**：中国体育彩票、中国福利彩票官方公开历史开奖接口；缓存到 `work/lottery/`，
  默认 6 小时内复用，页面显示最新期号、开奖日期、抓取时间；接口失败时用缓存并明确提示。
- **走势统计**：冷热号、遗漏值、和值、奇偶比、三区分布、连号、重号，以及最近 5 期开奖。
- **选号策略**：随机均匀、热号加权、冷号加权、近期趋势、区间均衡；随机种子可填写，填相同种子可复现。
- **注数计算**：复式按组合公式展开，胆拖按 `C(拖码, 需要补足的数量)` 计算；金额 = 注数 × 单注金额。
- **保存与核对**：生成后点「保存这组号码」写入 `work/lottery/saved.json`；历史记录可删除、可核对开奖。
  核对时使用「参考期号的下一期」官方开奖，复式/胆拖会先展开成基本投注再逐注计算奖级和奖金。
- **奖级规则**：大乐透按 2026 年 1 月新规则（7 个奖级），追加只参与一、二等奖；
  双色球按 6 个奖级；快乐8 按「选 k 中 m」查当期官方奖金表。奖金优先取当期官方公告金额。

**注意**：

- 复式/胆拖数量上限是本工具为控制注数设置的保护值，不是官方上限，具体以官方规则为准；
- 大乐透这里只做前区胆拖，后区固定 2 个号；快乐8复式上限 15 个号，胆拖拖码最多 `80 - 胆码个数`（选五 4 胆拖 2 = 2 注，4 胆全拖 76 个号 = 76 注）；
- 套餐票在本工具里是「N 注单式」的模拟套餐，不是官方套餐产品；
- 核对结果按官方开奖号码自动计算，实际兑奖以官方终端为准；
- 所有结果**仅供娱乐参考，不预测开奖，不构成任何购彩建议**。

实现：`xhs/lottery.py`、`static/tools/lottery.html`；接口 `GET /api/lottery/games`、
`POST /api/lottery/simulate`、`GET/POST /api/lottery/saved`、
`POST /api/lottery/saved/{id}/check`、`DELETE /api/lottery/saved/{id}`；
离线测试 `python tools/check_lottery.py`。

## 竞彩足球参考（彩票工具内）

彩票页面顶部新增「⚽ 竞彩足球」模式，按竞彩销售日选择日期，一键获取当天场次和参考推荐。

- **数据来源**：500.com 竞彩足球页面（赛程、竞彩编号、中文联赛/球队名、胜平负、比分、半全场、总进球赔率）；
  中文队名和编号与体彩 app 对齐，页面会显示来源和抓取时间。
- **统计方式**：每个玩法分别用真实赔率去抽水，得到隐含概率；比分、半全场、总进球直接按对应玩法赔率排序，
  不是另外用泊松模型编出的数。
- **场次口径**：按「周五/周六…」销售日筛选，包含次日凌晨比赛，和体彩 app 的周X场次一致；
  以 2026-10-23 周五为例返回 12 场。
- **输出**：每场比赛显示竞彩编号、联赛、开赛时间、中文队名、市场概率、期望总进球，
  以及比分、半全场、总进球三组参考项；没有对应赔率的比赛会标「数据不足」，不编造推荐。
- **未接入**：伤停、阵容、历史交锋；页面会明确说明，避免把赔率概率当成完整分析。
- **免责声明**：所有推荐仅供娱乐参考，不构成投注建议；赔率会变化，请以体彩官方为准。

实现：`xhs/football.py`、`static/tools/lottery.html`；接口 `GET /api/football/daily?day=YYYY-MM-DD`；
离线测试 `python tools/check_football.py`。

## 学习路径与考核

按主题、当前基础和目标水平，生成 2~8 个递进阶段，并为每阶段配置学习内容、资源入口、考核重点和实操作品。

- **模型设置**：工具内可单独选择「跟随工具箱 / DeepSeek / 自定义 OpenAI 兼容」，
  也可以单独填模型名、Base URL 和 API key；默认跟随工具箱的总结模型。
  工具箱首页左下角「⚙ 默认模型设置」控制所有未单独覆盖的工具；工具自己的模型设置优先级更高。
- **资源**：AI 只给资源名称和搜索词，程序生成 Bing / GitHub 搜索入口；
  教材、课程、视频统一走 Bing，避免豆瓣/B 站搜索页出现验证页或空白。
  不编造具体课程、书号或链接；资源是否适合仍需自己判断。
- **考核**：每阶段 AI 生成 10 道单选题，程序自动判分，**80 分通过**；

- **持久化**：计划、阶段状态、每次得分和作废记录保存在 `work/learning/plans.json`。
- **说明**：选择题只能检验部分理解；每阶段的实操作品建议自己保留，作为真正的能力证据。

接口：`POST/GET /api/learning/plans`、`GET/DELETE /api/learning/plans/{id}`、
`POST /api/learning/plans/{id}/stages/{index}/exam|submit|reset`、
`GET/POST /api/learning/settings`；

## 代码审查（OpenCodeReview）

把阿里开源的 [OpenCodeReview](https://github.com/alibaba/open-code-review) 接进工具箱，对本地项目做代码审查并生成 Markdown 报告。

- **两种模式**：`scan` 全量扫描不需要 Git diff；`review` 审查当前未提交/暂存的 Git 变更。
- **快速审查（默认）**：只挑最近修改的 5 个源码文件，自动排除 `_vendor`、`node_modules`、`output`、`work`、构建产物和锁文件，明显降低耗时与 token；要看整个项目时取消勾选即可。
- **路径选择**：支持直接粘贴路径（文件夹或单个文件），也可以点「📁 选择文件夹」用系统选择框选目录；单文件会自动走全量扫描。
- **中文报告**：OCR 的 `language` 已设为 `zh`，新生成的评论和总结使用中文；历史报告不会自动翻译。
- **人工核查**：报告固定包含「需要人工核查」，列出高危/中危项，并说明 AI 未验证的运行时、业务规则、依赖、测试、性能、并发等范围。
- **模型**：工具内可单独选「跟随工具箱 / DeepSeek / 自定义 OpenAI 兼容 / 本地模型」；
  没单独设置时使用首页「⚙ 默认模型设置」。
- **报告**：JSON 原始结果 + Markdown 报告，保存到 `work/codereview/`；页面可在线查看、下载 Markdown 和 JSON。
- **CLI**：也可以直接跑
  ```powershell
  python tools/review_project.py --project E:\path\to\project
  ```
- **OCR 二进制**：默认找 `_vendor/ocr/ocr.exe`，也支持环境变量 `OCR_BIN`。
  当前本机已放入 v1.13.3；它约 58 MB，不提交 Git。换电脑时从
  [Releases](https://github.com/alibaba/open-code-review/releases) 下载 Windows amd64 版放到该路径，
  或运行 OCR 仓库里的 `install.ps1`。
- **注意**：代码会被发送给默认模型服务；AI 审查可能误报/漏报，报告不替代人工评审。
- **token 预算**：默认 0（不限）；如果设得太低，OCR 会跳过文件并在报告里写运行警告。

实现：`xhs/review.py`、`static/tools/code-review.html`；接口 `GET /api/review/info`、
`POST /api/review/run`、`GET /api/review/report/{id}`、`GET /api/review/json/{id}`；
离线测试 `python tools/check_review.py`。

## 小红书视频转笔记

粘贴一条小红书分享链接，工具会自动下载视频、把语音转成文字，然后**按内容类型**整理成 markdown：
讲工具就给工具清单 + 作用 + GitHub 链接，问答就逐条对应问题与回答，教程就按知识点复述，
观点分享、资讯各有对应结构。像「本周热榜」「本周新增 9.9k star」「点点关注」这类信息会被明确剔除。

```
分享链接 → 解析短链 → 下载视频 → 抽音轨 → 云端转写 → 判断内容类型 → 核实 GitHub 链接 → 写 md
```

内容类型由模型判断，共六类：**工具推荐 / 问答 / 教程讲解 / 观点分享 / 资讯 / 其它**；
文档结构随类型变化，但「只要视频里提到工具，就给作用 + 项目地址」这条规则对所有类型都生效。
文档讲的是**视频里的内容**；作者正文只作为专有名词的核对参考喂给模型，不会写进文档（可在设置里关掉）。

**关于 GitHub 链接的可信度**：链接不是让大模型凭记忆写的（它很会编）。流程是先用接口验证
原文/模型给出的仓库确实存在，都没有才按仓库名搜索，且要求名字对得上、star 数过得去；
实在找不到就老实写「未找到公开仓库」。每条链接都带来源和可信度标注：

| 来源标记 | 含义 |
|---|---|
| 原文给出 | 笔记正文里的链接，已确认仓库存在 |
| 模型提供，已验证 | 模型写的 owner/repo，接口确认存在才采用 |
| 自动匹配（名字完全一致） | 搜到的仓库名与工具名一致 |
| 自动匹配（名字相近，请核对） | 名字只是相近，可能是第三方包装项目。**默认不采用**，见下方说明 |
| 未找到公开仓库 | 确实没有可信的仓库，不硬凑 |
| 本次未查询成功（限流） | 查不了 ≠ 不存在，会分开写 |

「名字相近」这一类**默认直接丢掉**（宁可写「未找到」也不给可疑地址）：实测中所有误配都出自这一类，
典型是商业产品的同名小仓库、第三方包装项目（例如把商业产品名匹配到某人写的 API 面板）。
想让匹配更宽松，把 `config.json` 里 `github.allow_loose_match` 改成 `true`，此时这类结果会带着
「名字相近，请核对」标记出现。

## 二、用法

1. 把小红书 App 的分享链接粘进输入框，**一行一条**，支持一次贴多条批量处理。
   整段分享文案直接贴也行（"看看这个 … 复制打开小红书"），会自动把链接抠出来。
2. 点「开始生成」，进度条按六个阶段推进：解析链接 → 下载媒体 → 提取音频 → 语音转写 → 生成总结 → 写入文件。
3. 完成后结果卡片里可以直接**查看内容**、**下载 md**；页面上还有「已生成的笔记」列表和「打开文件夹」。

补充说明：

- **文档随内容类型变**：工具推荐 / 问答 / 教程讲解 / 观点分享 / 资讯 / 其它，各自有对应结构；
  只要视频里提到工具，就会给「工具名 + 作用 + GitHub 地址」，找不到就写「未找到」。
- **文档讲的是视频内容**：作者写的正文只作为「专有名词核对表」喂给模型，**不会写进文档**；
  想彻底不给模型看，就在设置里取消勾选那一项。
- **噪音会被剔除**：热榜排名、star 涨量、「点点关注」、话题标签、口播寒暄都不进正文
  （完整逐字稿里保留原始口播，因为那是记录）。
- **GitHub 链接开关**：设置里有「自动给提到的工具匹配 GitHub 仓库」，不想让它去查就取消勾选
  （此时文档里所有项目地址都写「未找到公开仓库」，不会有编造的地址）。
- **文档开头没有元数据块**：默认直接从 `# 标题` 开始（来源、作者、类型、时长都在下面那行引用里）。
  需要机器可读的 YAML 元数据时，在设置里勾上「在文档开头输出 YAML 元数据块」。
- **图文笔记**（没有视频的笔记）：下载器拿不到视频时会自动改用笔记正文来总结，不会直接失败。
- **长视频**：音频会按时间切片（默认 600 秒一段）逐段转写，再拼回完整逐字稿，时间戳会自动接上。
- **中间产物**：处理完成后会删掉下载的视频和音频切片；想留下就把设置里的「保留下载的原始视频」勾上。
- **输出目录**：默认项目内的 `output/`，可在设置里改成绝对路径（例如 `D:\笔记`）。

## 五、常见问题

**某条视频跑到一半失败，或提示「有 N 段音频转写失败」**
长视频的音频会切片上传。单段遇到接口 5xx 会重试（默认 4 次，间隔 2/4/8 秒），仍然失败时：
- 只失败部分段落 → **照样生成文档**，并在开头用 ⚠️ 标注缺了哪几段，已成功段落的内容不会白跑；
- 全部段落都失败 → 才判定失败，并逐段列出原因。

重试次数可在 `config.json` 里改（`asr.retry_attempts`）。

**提示需要登录 / 下载失败**
小红书对未登录请求有风控。把设置里的「浏览器 Cookie 来源」选成你**已登录小红书**的浏览器
（Edge / Chrome / Firefox），并**把这个浏览器完全退出**再重试——浏览器开着时它的 cookie 数据库
被占用，读不出来。工具在读不到 cookie 时会自动改为不带 cookie 重试一次，所以公开笔记仍然能处理。

**本机开着代理（如 127.0.0.1:7897）**
下载默认**直连**。原因有两个：yt-dlp 不像 requests 那样按系统设置里的例外名单绕过 `127.*`，
开着代理时连本地地址都会被拦；而小红书是国内站点，走海外节点容易触发风控。
确实需要走代理，就在设置里填代理地址或勾上「下载时使用系统代理」。
（转写和总结接口走的是 requests，仍然遵循系统代理；想让它们也直连，可设置环境变量
`NO_PROXY=api.deepseek.com,api.siliconflow.cn`。）

**报 `[Errno 13] Permission denied` 或临时目录相关错误**
受限环境下 Python 用 `0o700` 建临时目录会丢掉继承来的权限项，导致目录建得出来、文件写不进去。
程序启动时会自动探测并打兼容补丁（见 `xhs/sandbox.py`），日志里会出现一行提示，属正常。

**转写或总结报 401 / 402 / 429**
401 是 key 不对，402 是余额不足，429 是限流。设置面板里的「测试」按钮会直接告诉你具体原因。

**文档里某个工具写着「未找到」**
说明没找到可信的仓库：要么名字太泛（比如「PS5 游戏移植」这种中文描述），要么它不在 GitHub 上。
按「宁可没有链接，也不给错链接」的原则，这种情况不会硬凑一个地址。想提高命中率，可以在设置里的
「额外总结要求」写上工具的准确拼写，或者填一个 GitHub Token（未认证时每小时限 60 次查询）。

**文档里写着「本次未查询成功（GitHub 接口限流）」**
未认证的 GitHub 查询每小时只有 60 次，而且在走代理时出口 IP 常常是很多人共用的，很容易撞上。
这时文档会如实标注「查询失败」——是**查不了**，不是这个工具没有仓库（两者会分开写，别混淆）。
解决办法：在设置里填一个 GitHub Token（<https://github.com/settings/tokens> 生成，不勾任何权限即可读公开仓库），
额度会提到每小时 5000 次。

**GitHub 链接旁边标着「自动匹配（名字相近，请核对）」**
标这个表示地址是**按仓库名搜索**出来的，且仓库名只是与工具名相近，存在同名或第三方包装项目的可能，
点开确认一下最稳妥。标「名字完全一致」的把握更大；标「模型提供，已验证」的表示模型给出的
owner/repo 经接口确认存在；标「原文给出」的最可信。

**成本大概多少**
一条 3 分钟视频：SenseVoice 转写约几分钱，DeepSeek 总结约几分钱，合计通常不到 1 毛。

**刷新页面 / 重启服务后作业记录没了**
作业状态只存在内存里。已经生成的 md 文件不受影响，页面下方的文件列表会从磁盘重新读取。

**要不要升级 yt-dlp**
小红书改版后解析可能失效，届时执行：

```powershell
python bootstrap_deps.py --upgrade --only yt-dlp
```

## 七、怎么再加一个工具

在 `static/tools/` 里放两个文件，刷新页面即可，**不需要改 Python 代码**：

1. `static/tools/<工具id>.html` —— 工具自己的页面（HTML + CSS + JS 都写在这一个文件里，
   页面之间用 iframe 隔离，所以不用担心样式或变量互相影响，接口按 `/api/...` 写绝对路径）。
2. `static/tools/<工具id>.meta.json` —— 它在左侧列表里怎么显示：

```json
{
  "name": "税率计算器",
  "description": "增值税价税分离：含税/不含税金额与税额互算",
  "icon": "🧮",
  "order": 20
}
```

- `order` 决定列表顺序（小的在前），不写默认 100；
- `meta.json` 可以不写，此时列表里用文件名当名称、图标用 🔧；
- 页面地址是 `/tool/<工具id>`，工具 id 只允许字母、数字、下划线、短横（防止路径穿越）。
- 需要共用样式或计算逻辑时，把文件放进 `static/tools/_shared/`，页面里按绝对路径引用即可，例如
  `<link rel="stylesheet" href="/static/tools/_shared/base.css">`、
  `<script src="/static/tools/_shared/finance.js"></script>`。`_shared` 目录不会被当成一个工具。
  多个工具共用同一份计算代码（而不是各抄一遍），才不会出现「同一个公式在两个工具里算得不一样」。

程序启动时扫描这个目录（`app.py` 里的 `discover_tools()`），所以加完文件刷新浏览器就行，
连服务都不用重启 —— 除非你改了 `app.py` 这类 Python 代码。

> 想自动启动/定时跑某个工具，也可以在 `xhs/` 下按同样的方式加模块，
> 页面只是它的一个调用入口。

## 八、换一台电脑怎么用

整个工具是**自包含**的：不依赖系统里装过哪些 Python 库（实测用 `python -S` 禁用全部系统包也能启动）。
所以最省事的做法就是**把整个文件夹拷过去**。

### 用 Git 同步（推荐长期用）

项目里已经有 `.gitignore`，它会排除 `_vendor/`、`_wheels/`、`output/`、`work/`、
`config.json`、`tools/_selfcheck/` 和 `__pycache__/`，所以推到仓库的只有代码和文档，体积很小。

在一台电脑上建私有仓库（GitHub / Gitee 都行，不要勾选自动生成 README）：

```powershell
cd E:\AISoft\xhs-summarizer
git init
git add .
git commit -m "工具箱：笔记 + 税率 + 英语 + 多语言关键字"
git branch -M main
git remote add origin <你的私有仓库地址>
git push -u origin main
```

另一台电脑：

```powershell
git clone <你的私有仓库地址> D:\工具箱\xhs-summarizer
cd D:\工具箱\xhs-summarizer
python bootstrap_deps.py     # 下载依赖到本机 _vendor
python run.py
```

`config.json` 不在仓库里，需要单独用 U 盘/密码管理器拷过去，或者在新电脑的设置里重新填 key；
`output/` 里的笔记也不会进仓库，想同步笔记可以单独用 OneDrive / 坚果云 / Syncthing 同步这个目录。
以后改代码：工作电脑 `git push`，家里 `git pull` 即可。

> 不要把 `config.json` 提交到 Git，也不要把带 key 的整个目录直接放进公共网盘。
> 如果家里电脑不是 Python 3.13，不要拷 `_vendor`，直接在本机跑 `python bootstrap_deps.py`。

### 要拷什么

| 目录 / 文件 | 大小 | 要不要拷 | 说明 |
|---|---|---|---|
| `_vendor/` | 约 115 MB | **必须** | 全部依赖，含自带的 ffmpeg（约 84 MB）和 Web 框架 |
| `run.py`、`app.py`、`xhs/`、`static/`、`tools/`、`bootstrap_deps.py`、`README.md`、`requirements.txt`、`config.example.json` | 不到 1 MB | **必须** | 程序本体 |
| `config.json` | 几 KB | 看情况 | **里面是明文 API key**。拷过去省得重填；不想带着 key 走就别拷，到新电脑在网页设置里重填 |
| `output/` | 视笔记多少 | 看情况 | 已生成的 markdown 笔记，想留就拷 |
| `_wheels/` | 约 33 MB | 可不拷 | 只是下载缓存，仅在「没网、要靠 `bootstrap_deps.py` 重装依赖」时才有用 |
| `work/`、`__pycache__/`、`tools/_selfcheck/` | — | 不用拷 | 中间产物与缓存 |

**最小可运行拷贝约 115 MB**；连 `_wheels/` 一起拷约 148 MB。

不想用 Git 也可以直接拷 U 盘/移动硬盘。用 OneDrive、坚果云、Syncthing 同步时，
先停止服务再让它同步，避免 `output/` 和 `config.json` 同时被两边写入；`_vendor` 有 115 MB，首次同步会比较慢。

### 新电脑需要什么

1. **Windows 64 位 + Python 3.13**。
   `_vendor` 里的 `pydantic_core` 是编译好的二进制（`_pydantic_core.cp313-win_amd64.pyd`），和 Python 小版本绑定。
   如果新电脑的 Python 不是 3.13，**不要直接拷 `_vendor`**，改在那边执行 `python bootstrap_deps.py`
   （它会按本机解释器挑对应的 wheel）。
2. **网络**：下载小红书视频、调用转写与总结接口、查 GitHub 仓库都需要联网。
3. **浏览器登录状态**（可选）：需要登录才能看的笔记靠**本机浏览器**的 cookie，
   所以要在这台电脑的浏览器上登录小红书，并在设置里把「浏览器 Cookie 来源」选成它。
4. **Node.js**（可选）：只有跑 `node tools/check_finance.js` 这个金额计算测试才需要，日常使用不需要。

### 到了新电脑怎么起

```powershell
# 放哪都行，路径没有写死
cd D:\工具箱\xhs-summarizer
python run.py
```

如果没拷 `_vendor`（或 Python 版本不匹配）：

```powershell
python bootstrap_deps.py     # 重新下载依赖到项目内的 _vendor
python run.py
```

依赖不全时页面和终端会直接提示「依赖不完整，请先运行 python bootstrap_deps.py」，不会让你卡在半路猜原因。
端口被占用就换一个：`python run.py --port 9000`。

### 换机后建议跑一次自检

```powershell
python tools/selfcheck.py      # 90+ 项：下载 → 抽音轨 → 切片 → 转写 → 提取工具 → 核实链接 → 写 md
node tools/check_finance.js    # 67 项：个税、社保、摊还、提前还款、IRR（有 node 才跑）
```

## 九、已知限制

- **阿里云百炼那条转写路径（`qwen3-asr-flash`）是按官方文档实现的，还没有用真实 key 验证过**；
  硅基流动和 OpenAI 走的是同一个标准接口，接口形状已用本地假服务完整验证。
- **小红书抓取依赖 yt-dlp 的解析器**，站点改版后可能失效，需要升级 yt-dlp；图文兜底依赖页面里的
  `__INITIAL_STATE__`，页面结构变化时会失效（此时会给出明确报错，不会静默出错）。
- **自动匹配的 GitHub 链接仍可能误配**（同名项目）。默认只接受「仓库名与工具名完全一致」的匹配，
  名字相近的一律丢弃并写「未找到」，所以链接偏少但更可靠；要更宽松可打开 `github.allow_loose_match`。
- 服务只监听 `127.0.0.1`，没有登录鉴权，**不要**改成监听 `0.0.0.0` 暴露到公网。
- 作业历史存在内存里，重启即清空（产出文件不受影响）。
